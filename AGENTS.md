# AGENTS.md — focushouse

Read this first. Full requirements Q&A log is in `NOTES.md`.

## What this is
SwiftUI app for students and teenagers, iOS 17+ (built with the iOS 27.2 SDK). Below iOS 26 it runs in manual mode (no Apple Intelligence); the photo check and Siri reminders need iOS 27. AI code is marked `@available(iOS 26, *)` and gated by `Planner.isAvailable`. On-device Apple Foundation Models splits a goal or to-do list into tasks, estimates how long each takes, and suggests a timed schedule. Everything stays on device: no backend, no accounts, no Google sign-in.

- Project is generated by xcodegen (`project.yml`). Add new files via `project.yml` sources, then run `xcodegen`.
- Work on branch `machine-learning`. Repo: https://github.com/swiftinsg/focushouse (public).

## Decisions (locked)
- **Two input modes (toggle):** Goal mode (one big goal → tasks spread over days) and Today mode (messy to-do dump → tidied, timed, fitted into today).
- **Free time:** iOS Calendar events (EventKit) as busy time. Google Calendar arrives via iOS account sync, so no Google API (onboarding tip explains setup). Optional self-set routine (school hours, bedtime). A Settings option asks for free time each time instead.
- **Output:** schedule lives in-app with checkboxes, plus an "Add to Calendar" button. A Settings toggle auto-adds to the calendar once a schedule is suggested.
- **Notifications:** local reminder at task start; end-of-task check-in "Done? / Need more time?".
- **Rescheduling:** default is plain-code push-back (+15/+30/+60 min shifts later tasks; overflow past bedtime → tomorrow). Plus a "Re-plan with AI" button.
- **Editing before accept:** full control: rename/add/delete tasks, change durations (auto-reflow), drag-and-drop on a timeline. "Try again" regenerates.
- **No Apple Intelligence** (older device / turned off): manual mode, where the student enters tasks and durations. Scheduling, calendar, reminders and check-ins still work; AI features are hidden.
- **Adaptive estimates (must be personalised):** save plans and actual durations (from check-ins) on device; feed per-category actual/estimate ratios into the model prompt. The student can set a category's pace in Settings → My pace (its own page); finished tasks keep refining it.
- **House (main page):** Home tab shows a pixel house: the student's design (`Art/house_reference.png`, traced to `Art/house_reference.txt`), 96×64. `python3 tools/house_art.py && python3 tools/sprites.py` builds `house.<state>.<level>` PNGs. Level 0–5 comes from bricks earned all-time (`House.levelBricks`): run-down at first, fixed up as bricks come in, 4 = the design, 5 adds flowers. Several stressful days in a row damage it (Calm → Stressed → Overloaded → Crumbling); rest repairs one step per day with 3h+ of rest in waking hours (Resting). Rest = Screen Time (FamilyControls `.individual` + DeviceActivity): each waking hour with under 2 min of phone use counts, recorded by the `RestMonitor` extension into the App Group (`Shared/RestLog.swift`). Settings toggle "Count rest with Screen Time"; when off, time away from the app counts instead. Needs a real device. Logic in `House.swift`. All states and levels are the same house: damage only lands on house pixels (asserted in `tools/house_art.py`).
- **Stress:** the AI scores each task, Tasks-tab item and Calendar event 1–10 from its title (cached by title), scaled by the student's pace for that category; ranges 1–3 easy, 4–6 normal, 7–8 hard, 9–10 intense. Easy adds no stress; compulsory things (exams, lessons, set deadlines) count half. The student can set their own pre-task stress (slider in the to-do and task editors, and in New Plan for every task of a Today list or goal; without Apple Intelligence New Plan's slider is saved on the plan and given to tasks typed in by hand): it is the baseline, and their pace doesn't scale it. After each check-in, the AI (once there are 3+ check-ins) nudges a title's score −1/0/+1 from feeling, time and note; without Apple Intelligence plain code nudges one step toward how it felt. With no score, stress comes from how that title or category felt in check-ins (5 if nothing). Priority never feeds stress. The task editor's slider defaults to the hardest subtask's score.
- **Bricks (points):** finished tasks earn 1 per 10 min of the estimate or the real time, whichever is less, up to 2 h a task (×1.5 hard, ×2 intense, 0 easy; ×1.5 more when Screen Time saw the phone down the whole task; to-dos 3 each, 10 a day). Without Apple Intelligence a finished plan task earns its stress score instead (1 easy … 10 very stressful, ×1.5 phone down), whatever its length. A check-in photo the on-device model matches to the task adds +20% (at least 1); optional, never required, since many tasks have nothing to photograph (`Proof.swift`; camera only, photos kept on device 30 days). Counted on the day ticked (`doneAt`); ticking before the start earns nothing. Each day: full rate to 60, half after, capped 100. Weekly summary nudges when many ticks come within a minute. Bricks buy furniture in Upgrades ("Decorate with bricks" inside the house; the Home brick counter is display only): `Art/furniture.json` + `Art/furniture_hobbies.json` (DeepSeek-researched teen hobbies, `Art/hobby_research.md`) + `Art/furniture_more.json` (16 more: Work groups by DeepSeek, hobby groups by HY4, via opencode), drawn at runtime by `PixelSprite`. Lv 2 needs the Lv 1 of the same group; balance = earned − spent (owned names in UserDefaults "owned"). Earned all-time they fix up the house's condition; they never heal stress damage. Owned furniture goes inside the house: tap the house's door on Home to go inside (full-screen zoom out of the doorway), a 2D pixel cutaway of two storeys (`RoomView`, 134×202): downstairs has a fireplace under the chimney and stairs up (fixed art by HY4 via opencode, `Art/room.json`); `Shop.spots` gives 7 floor spots and 4 wall spots. Items with `"wall": true` (Wall Calendar, Cork Pinboard, Revision Whiteboard, Focus Clock) hang on wall spots, the rest stand on floor spots; an upgrade that changes kind moves via `Shop.refit`. Drag to move between spots or drop from "Your things" in Upgrades (UserDefaults "placed", one group per spot). Art work (sprites) goes through opencode with HY4 (`opencode/hy4-flash-free`). Widgets show only the exterior. Animations (all respect Reduce Motion): room fire flicker (HY4), embers, candle, Pommy the cat (hand-drawn from photos by `tools/pommy.py` into `Art/room.json` catWalk (four legs)/catSleep/catHang) walking and napping inside; drag her to carry her by the scruff (she swings against the finger's sideways speed, then drops to that floor and walks home or naps upstairs) and napping on Home's front step when calm or resting; Home sky follows the clock (`SkyClock` in `Theme.swift`: night/dawn/day/dusk, moon, stars, lit windows); level-up build sequence (`seenHouseLevel`); check-in bricks fly to the counter (`BrickBurst.swift`); AI planning shows `BrickLoader` and deals new task rows in; feeling buttons wiggle; timeline now-line pulses; Calendar rings sweep in; widget house sparkles for 3 h after rest repairs it.
- **Widgets (WidgetKit):** House (S), Today 3/7 (S), House + Next task with Done/+15/Take a break (M), My Day (L), Week work vs rest (M), Lock Screen circular/rectangular/inline. Data via App Group snapshot. Widget ticks give bricks only after "How did it go?" is answered. Lock Screen hides task names while locked. Settings toggle "Show house damage on widgets". Rest overlapping scheduled tasks/lessons doesn't count. Details in `NOTES.md`.
- **Study material attachments:** New Plan's Study material box takes photos (PhotosPicker) or PDFs/images (Files). Text comes out on device (PDFKit text layer, Vision OCR for photos and scanned pages); over 1500 characters, the model outlines it into one "Name - points" line per section (max 15) so the planner makes one item per section. Files aren't kept, only the text. Logic in `StudyMaterial.swift`.
- **Siri & Spotlight (App Intents):** plan tasks and to-dos are shared as reminders (`@AppEntity(schema: .reminders.reminder)`, `IndexedEntity`) with their stress score in the note and tags, indexed on device when the app goes to the background. "How's my house?" / "How stressed am I?" in focushouse answers with the house state, today's progress, the hardest task left and what's next (needs unlock). Siri's create-reminder action adds a to-do. Ticking done through Siri isn't offered: bricks need the check-in. Logic in `SiriIntents.swift`.
- **Tabs:** Home · Schedule · Calendar. Schedule holds to-dos (the old Tasks tab, `TodoItem`) above plans; + adds either. Lists use `PixelList` (square bordered sections), headers `.pixelHeader()`, main buttons `.buttonStyle(.pixel)`. Settings opens from Home's gear button. Pixel theme: Pixelify Sans for headings, square borders, brick meters; body text stays system font.

## Build plan (phases, test each before the next)
1. **Core:** mode toggle → Foundation Models decomposition + estimates → schedule into routine free time → editable list with auto-reflow → SwiftData persistence. Manual-mode fallback.
2. **Calendar:** EventKit read of busy time, Add to Calendar, auto-add toggle, "ask each time" setting, Google-sync onboarding tip.
3. **Reminders & check-ins:** start notifications, end-of-task check-in, push-back, Re-plan with AI.
4. **Timeline:** drag-and-drop tasks between time slots.
5. **Adaptive estimates:** record actuals, inject per-category ratios into the prompt.
6. **Reflections:** check-in asks time taken, how it felt (1–5) and an optional note (on device, notes auto-delete after 30 days). AI infers best hours, moves hard tasks there, splits draining tasks, adds breaks after hard days, writes a weekly insight card. Daily work limit set by the student (default 3h school days / 4h off days); New Plan warns and adds free time above it.
7. **Widgets (WidgetKit):** see Decisions.
8. **Study material attachments:** see Decisions.
9. **Siri & Spotlight:** see Decisions.

## Working rules
- Build one phase at a time; stop after each phase for the user to test.
- Keep it minimal: Apple frameworks only (FoundationModels, SwiftData, EventKit, UserNotifications). No third-party dependencies.
- Scheduling, push-back, stress and bricks are plain deterministic code. Only decomposition, estimates, Re-plan and stress scores use the model.
- Commit and push to `machine-learning` at the end of each phase.
